# GetGantt CLI

## 1. Установите CLI

Запустите в терминале:

    npm install --global getgantt-cli
    gantt --help

Нужен Node.js 22 или новее.

## 2. Если CLI должен установить агент

Скопируйте агенту эту инструкцию:

    Установи глобально пакет getgantt-cli командой
    npm install --global getgantt-cli.
    Затем выполни gantt --help и сообщи, удалось ли найти команду gantt.
    Не запрашивай у меня personal access token в чате.

CLI должен быть установлен именно в том окружении, где агент запускает
команды. Установка на вашем компьютере не поможет облачному агенту, если он
работает в другом окружении.

## 3. Установите skill для Codex

Skill нужен, чтобы Codex сам знал правила работы с GetGantt: как выбрать проект,
когда использовать preview и как проверять результат изменения.

Скопируйте Codex эту инструкцию:

    Установи skill GetGantt CLI из GitHub:
    https://github.com/simon100500/getgantt-cli/tree/main/skills/getgantt-cli
    После установки используй этот skill для всех операций с моим графиком GetGantt.

После установки начните новый запрос или новый чат. Если вы используете не
Codex, положите файл AGENTS.md из этого репозитория в проект, где работает
агент.

## 4. Подключите аккаунт GetGantt

Выпустите personal access token в личном кабинете GetGantt. Затем запустите:

    gantt auth login

Вставьте токен в скрытое поле. Сам токен агенту отправлять не нужно.

Проверьте подключение:

    gantt auth status

Если агент работает в другом окружении, авторизацию нужно выполнить там же.

## 5. Дайте агенту инструкцию по работе с графиком

Скопируйте агенту этот текст. Вместо <PROJECT_ID> укажите ID нужного проекта:

    Ты управляешь моим графиком GetGantt через CLI gantt.

    Мой проект: <PROJECT_ID>

    Правила работы:
    - работай только с указанным проектом;
    - сначала прочитай текущий график и найди нужные задачи;
    - перед любым изменением сначала покажи мне план и выполни preview;
    - не применяй изменение без моего отдельного подтверждения;
    - после изменения сообщи, что именно изменилось и какая версия графика стала новой;
    - используй gantt --json для чтения;
    - не выдумывай ID задач или проекта;
    - если есть несколько подходящих задач или проектов, сначала покажи варианты и спроси меня.

Если ID проекта неизвестен, вместо этого напишите агенту:

    Покажи список моих проектов GetGantt. Я выберу проект, после чего работай только с ним.

## 6. Что можно писать агенту

После подключения не нужны специальные команды — пишите обычными словами:

    Покажи все этапы работ.
    Найди задачу «Фундамент» и покажи её зависимости.
    Создай этап «Монтаж» длительностью 10 рабочих дней.
    Поставь задачу «Установка окон» после «Кладки стен».
    Покажи задачи с просроченным сроком.
    Сдвинь весь график на 3 рабочих дня.
    Удали задачу «Черновик».

Агент умеет показывать проект, этапы, задачи, иерархию и зависимости, проверять
расписание, создавать и изменять задачи, перемещать их между этапами,
связывать зависимости, сдвигать расписание и удалять задачи.

Перед изменением агент сначала делает preview. Preview ничего не меняет.
Изменение считается выполненным только после подтверждения успешного
применения и новой версии графика.

## Если у вас несколько аккаунтов

Можно сохранить несколько профилей:

    gantt auth login --name work
    gantt auth login --name personal
    gantt auth profiles list
    gantt auth profiles use work

## Если агент не видит CLI

Проверьте в том же окружении, где работает агент:

    gantt --help
    gantt auth status

Если первая команда не работает, CLI не установлен или не добавлен в PATH.
Если не работает вторая, выполните gantt auth login в этом окружении.

## Безопасность

- не передавайте personal access token агенту в сообщениях;
- не вставляйте токен в команду или файл;
- всегда проверяйте preview перед изменением;
- при неоднозначном названии задачи просите агента сначала показать варианты.
